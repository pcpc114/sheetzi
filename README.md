# 시트지

구글 시트 같은 **협업 웹 스프레드시트**. 수식 엔진부터 실시간 동시 편집까지 직접 만들었습니다.
외부 스프레드시트 라이브러리도, 빌드 도구도, 데이터베이스 설치도 없습니다.

---

## 실행

Node 20.12 이상이 필요합니다 (`node -v` 로 확인).

```bash
npm install     # 최초 1회
npm start
```

브라우저에서 **http://localhost:3000** 을 엽니다. 문서 목록 화면이 뜹니다.

다른 포트를 쓰려면:

```bash
PORT=8080 npm start          # macOS / Linux / Git Bash
$env:PORT=8080; npm start    # PowerShell
```

### 설정은 `.env` 파일에 (읽습니다, 진짜로)

비밀번호나 저장소 같은 설정은 프로젝트 폴더의 **`.env`** 파일에 적습니다.
`.env.example` 을 복사해서 만드세요.

```bash
cp .env.example .env     # macOS / Linux / Git Bash
copy .env.example .env   # Windows 명령 프롬프트
```

- 서버(`npm start`)는 **시작할 때 이 파일을 읽습니다.** 값을 고쳤으면 서버를 껐다 켜야
  반영됩니다.
- `.env` 가 **없어도 정상**입니다. 아무 설정 없이 그냥 켜집니다.
- **같은 이름이 환경변수에 이미 있으면 환경변수가 이깁니다.** `.env` 는 그때 무시됩니다.
  Render·Railway 처럼 대시보드에 값을 넣는 곳에서 파일 없이도 그대로 동작하는 이유입니다.
- 어떤 값이 실제로 적용됐는지는 **시작 로그에 이름으로 표시**됩니다. 비밀번호나 키 같은
  값 자체는 절대 찍지 않습니다.

```
[시트지] .env 를 읽었습니다 (C:\...\시트지\.env)
[시트지] .env 에서 적용된 값: SZ_PASSWORD, SZ_SESSION_SECRET (값 자체는 기록하지 않습니다)
```

`.env 를 읽었습니다` 줄 자체가 안 보이면 `.env` 가 없거나 다른 폴더에 있는 것입니다. 파일
위치는 `package.json` 과 같은 폴더입니다. 파일은 읽었는데 값이 하나도 새로 안 들어갔다면
`[시트지] .env 를 읽었지만 새로 적용된 값이 없습니다` 가 대신 나오고, 같은 이름이 이미
환경변수에 있어서 밀린 값이 있으면 그 이름들도 한 줄로 따로 찍힙니다. 파일은 있는데 못 읽는
경우(권한 문제 등)에는 **서버가 아예 켜지지 않습니다** — 비밀번호가 빠진 채로 켜지는 것보다
안 켜지는 편이 안전하기 때문입니다.
메모장으로 저장한다면 인코딩을 `UTF-8`(BOM 없음)로 고르세요.

여기 넣을 수 있는 값 전부입니다. 하나도 안 넣어도 켜집니다.

| 이름 | 뜻 | 안 넣으면 |
|---|---|---|
| `PORT` | 서버 포트 | `3000` |
| `SZ_PASSWORD` | 접속 비밀번호 **원문** — 내 컴퓨터용 (아래 [접속 비밀번호](#접속-비밀번호)) | 잠금 꺼짐 |
| `SZ_PASSWORD_HASH` | 비밀번호를 원문 대신 해시로 — **인터넷에 공개하는 서버는 이쪽만** | — |
| `SZ_SESSION_SECRET` | 로그인 세션 서명용 임의 문자열 | 켤 때마다 새로 (모두 로그아웃) |
| `SZ_SESSION_DAYS` | 로그인 유지 기간 | `14` (최대 365) |
| `SUPABASE_URL` | 채우면 Supabase 에 저장 (아래 [저장소](#저장소--파일-또는-supabase)) | `data/` 폴더에 저장 |
| `SUPABASE_SERVICE_KEY` | Supabase 비밀 키 — `sb_secret_...` (또는 옛 `service_role`) | — |
| `SUPABASE_SCHEMA` | Supabase 스키마 이름 | `public` |

### 화면 구조

| 주소 | 화면 |
|---|---|
| `/` | **문서 목록** — 카드로 늘어놓고, 검색·정렬·만들기·이름변경·삭제 |
| `/edit#doc=<id>` | 스프레드시트 편집 |

편집 화면에서 **왼쪽 위 로고**를 누르면 문서 목록으로 돌아갑니다.
예전에 공유한 `/#doc=...` 형식 링크도 그대로 열립니다.

### 문서와 시트

- **문서** — 파일 하나. 목록 화면의 `새 문서 만들기`로 만듭니다. 편집 화면 헤더의
  `새 문서` / `내 문서` 버튼으로도 됩니다
- **시트** — 문서 안의 탭. 왼쪽 하단 `+`로 추가합니다. 탭을 더블클릭하면 이름을 바꾸고,
  탭의 화살표를 누르면 복사본 만들기 / 색상 변경 / 삭제가 나옵니다. 탭을 끌어서 순서를 바꿉니다

### 같이 편집하기

주소창의 URL(`http://localhost:3000/edit#doc=xxxxxx`)을 그대로 상대방에게 보내면 됩니다.
같은 문서에 들어온 사람의 커서와 이름이 실시간으로 보입니다.

**같은 컴퓨터가 아닌 사람과 쓰려면** 서버가 외부에서 접근 가능해야 합니다. 같은 공유기(집·사무실)
안이라면 `http://<내 컴퓨터 IP>:3000` 으로 접속하면 되고, 인터넷 너머라면 배포가 필요합니다.
아래 [배포](#배포) 참고.

## 기능

**수식** — `=` 로 시작하면 수식입니다. 셀 참조(`A1`, `$B$2`), 범위(`A1:B10`), 전체 열(`A:A`),
사칙연산, 비교, 문자열 결합(`&`), 백분율(`50%`)을 지원합니다.

내장 함수 **114개**:

| 분류 | 함수 |
|---|---|
| 수학 | `SUM PRODUCT ABS ROUND ROUNDUP ROUNDDOWN CEILING FLOOR INT TRUNC MOD POWER SQRT EXP LN LOG LOG10 SIGN PI RAND RANDBETWEEN GCD LCM SUMPRODUCT SUMSQ` |
| 통계 | `AVERAGE AVERAGEA MEDIAN MIN MAX COUNT COUNTA COUNTBLANK COUNTIF COUNTIFS SUMIF SUMIFS AVERAGEIF AVERAGEIFS STDEV STDEVP VAR VARP LARGE SMALL RANK MODE` |
| 논리 | `IF IFS AND OR NOT XOR TRUE FALSE IFERROR IFNA SWITCH` |
| 텍스트 | `CONCAT CONCATENATE TEXTJOIN LEN LEFT RIGHT MID UPPER LOWER PROPER TRIM SUBSTITUTE REPLACE FIND SEARCH REPT VALUE EXACT CHAR CODE TEXT` |
| 찾기 | `VLOOKUP HLOOKUP INDEX MATCH CHOOSE ROW COLUMN ROWS COLUMNS OFFSET INDIRECT` |
| 날짜 | `TODAY NOW DATE YEAR MONTH DAY HOUR MINUTE SECOND WEEKDAY DAYS EDATE EOMONTH DATEDIF TIME` |
| 정보 | `ISBLANK ISNUMBER ISTEXT ISERROR ISERR ISNA ISLOGICAL NA TYPE` |

**그 외**

- 문서 여러 개 — 만들기·목록·이름변경·삭제
- 시트 탭 — 추가·이름변경·삭제·드래그 순서변경·복제·탭 색상. 시트마다 데이터와 서식이 독립적입니다
- 실시간 동시 편집 — 셀 단위 최종 쓰기 우선, 상대 커서·선택 영역 표시.
  다른 시트에 있는 사람은 그 시트 탭에 점으로 표시됩니다
- 서식 — 굵게/기울임/밑줄/취소선, 맞춤, 글자색·배경색, 숫자·통화·백분율·날짜 서식
- 셀 병합·병합 해제
- 행·열 삽입·삭제 (수식의 참조가 자동으로 따라 바뀝니다), 열 너비 조절, 행·열 고정
- 데이터 정렬(오름차순·내림차순)과 필터
- 차트 — 라이브러리 없이 SVG로 직접 그립니다
- 댓글 — 셀에 메모를 달고 같이 보는 사람과 주고받습니다
- 인쇄 — 화면에 보이는 부분만이 아니라 시트 전체를 쪽 나눠서
- 복사·잘라내기·붙여넣기 — 시트지 안에서는 값·서식·수식이 모두 따라오고, 수식의 상대 참조는
  붙여넣는 위치에 맞춰 자동으로 조정됩니다
- **엑셀·구글 시트에서 가져오기** — 아래 [외부에서 가져오기](#외부에서-가져오기) 참고
- 실행취소·다시실행 (`Ctrl+Z` / `Ctrl+Shift+Z`)
- 자동 채우기 핸들 — 숫자는 등차수열, 수식은 참조 이동
- CSV 내보내기 (엑셀에서 한글이 깨지지 않도록 BOM 포함)
- 접속이 끊기면 자동 재연결
- 다크 모드 (OS 설정을 따라감)

### 기록이 날아가지 않게 하는 장치

이 프로젝트에서 제일 중요한 요구사항입니다. 지금 코드에 들어 있는 것만 적습니다.

- **모든 편집은 먼저 기록에 한 줄씩 덧붙여집니다** (파일 저장소면 `data/<id>.log`,
  Supabase 면 `sz_journal` 표). 그게 끝난 뒤에야 서버가 브라우저에 "저장됐다"고 답합니다.
  전체 JSON 스냅숏은 그 기록을 눌러 담은 요약본이지 원본이 아닙니다. 서버가 갑자기 죽어도
  다시 켜질 때 스냅숏 위에 기록을 다시 얹습니다.
- **브라우저는 저장 확인을 받기 전까지 편집 내용을 자기가 들고 있습니다**(`sz.outbox.<문서id>`).
  탭을 닫거나 브라우저가 꺼져도 남아 있다가, 다시 들어오면 순서대로 다시 보냅니다.
- **헤더의 저장 표시는 절대 앞질러 말하지 않습니다.** 확인 못 받은 게 하나라도 있으면
  `저장 중…`, 연결이 끊겨 있으면 `저장 대기 중 (N)` 이고, 전부 확인된 뒤에만 `저장됨` 입니다.
- 저장하지 못한 게 남은 채로 탭을 닫으려 하면 브라우저가 한 번 물어봅니다. 딱 한 경우만
  묻지 않는데, 로그인 화면으로 넘어갈 때(세션 만료나 로그아웃)입니다. 넘어가기 전에 못 보낸
  편집을 전부 브라우저에 넣어 두고 가고, 다시 로그인하면 그대로 이어서 보냅니다 — 물어봐야
  "머무르기" 를 눌러 봤자 저장이 안 되는 화면으로 돌아갈 뿐이라 일부러 그렇게 했습니다.
  (임시 보관 자체가 안 되는 브라우저에서는 이 경우에도 물어봅니다.)
- 스냅숏을 새로 쓸 때마다 직전 것을 백업으로 밀어 두고 **5벌**까지 보관합니다
  (파일이면 `<id>.bak.1` … `.bak.5`, Supabase 면 `sz_backups` 표).
  `GET /api/docs/<id>/backups` 로 무엇이 남아 있는지 볼 수 있습니다.

`npm run crash` 가 이걸 매번 확인합니다 — 서버를 강제 종료해 가며, 파일 저장소와 Supabase
저장소 양쪽에서.

여전히 보장하지 못하는 것은 아래 [한계](#한계) 에 적었습니다.

## 구조

```
server.js            Express + WebSocket + 실시간 프로토콜 + 접속 잠금
                     (문서를 읽고 쓰는 일은 전부 storage/ 에 맡깁니다)
env.js               시작할 때 .env 를 읽어 넣음 (server.js 가 가장 먼저 부름)
storage/             문서 저장소
  index.js             설정을 보고 아래 둘 중 하나를 고름
  fileStore.js         data/ 폴더의 파일 (기본값)
  supabaseStore.js     Supabase(Postgres)
shared/              ← 서버와 브라우저가 함께 쓰는 코드
  model.js             문서 모델·검증
  formula/
    tokenizer.js       수식 문자열 → 토큰
    parser.js          토큰 → 구문 트리(AST), 역직렬화
    evaluator.js       AST → 값
    functions.js       함수 114개
    function-docs.js   함수마다 한 줄 설명 (입력할 때 뜨는 도움말)
    engine.js          의존성 그래프 + 재계산
    refs.js            A1 ↔ 좌표, 범위, 참조 이동
    values.js          타입 변환, 날짜 일련번호
    errors.js          #DIV/0! 등 오류 값
public/              브라우저 (빌드 없는 ES 모듈)
  home.html            문서 목록 화면 (사이트 루트)
  index.html           편집 화면
  login.html           로그인 화면 (비밀번호를 걸었을 때)
  css/style.css        화면 전체 스타일 (다크 모드 포함)
  js/home.js           문서 목록 로직
  js/grid.js           그리드 렌더링·선택·편집
  js/main.js           편집 화면 조립
  js/net.js            WebSocket 클라이언트
  js/outbox.js         아직 저장 확인을 못 받은 편집 보관 (탭을 닫아도 남음)
  js/toolbar.js        툴바 + 수식 입력줄
  js/clipboard.js      복사·붙여넣기
  js/format.js         계산된 값 → 셀에 그릴 문자열
  js/history.js        실행취소·다시실행 스택
  js/schedule.js       화면 갱신 스케줄러
  js/sheetbar.js       왼쪽 하단 시트 탭
  js/docsmenu.js       문서 만들기·목록
  js/presence.js       헤더의 접속자 표시
  js/chart.js          차트 (SVG 직접 그리기)
  js/print.js          인쇄용 문서 만들기
  js/login.js          로그인 화면 로직
test/                단위 테스트
tools/               검증 도구 + 운영 도구(비밀번호 해시)
data/                문서 저장. 문서 하나가 파일 여러 개입니다 —
                     <id>.json(스냅숏) + <id>.log(기록) + <id>.bak.1..5(백업)
docs/SPEC.md         모듈 간 인터페이스 계약서
docs/supabase.sql    Supabase 를 쓸 때 한 번 실행하는 준비 SQL
docs/shots/          npm run browser 가 남기는 화면 스크린샷
.env.example         설정 예시 (복사해서 .env 로)
```

**수식 엔진이 `shared/` 에 있는 이유** — 같은 코드가 브라우저(입력 즉시 계산)와
서버(CSV 내보내기)에서 동시에 돕니다. 계산 로직이 두 벌로 갈라져 서로 다른 답을 내는 일이 없습니다.

## 검증

```bash
npm run verify
```

여덟 단계를 순서대로 돌립니다. 하나라도 실패하면 멈춥니다.

| 명령 | 내용 |
|---|---|
| `npm run check:imports` | 모든 파일의 import 정합성. `shared/` 에 Node·브라우저 전용 코드가 섞였는지도 검사 |
| `npm run check:spec` | `docs/SPEC.md` 대조 — 빠진 함수, 스텁, `TODO`, 외부 네트워크 참조, README 가 코드와 어긋나는지(있는 기능을 없다고 우기는 문장, 함수 개수, 함수 목록) |
| `npm run check:writes` | 저장소가 **읽어보지 않은 문서를 덮어쓰거나 지우지 못하게** 막는 관문이 제자리에 있는지. 파일을 만들고·고치고·옮기고·지우는 호출과 데이터베이스에 쓰는 호출이 전부 그 관문 안에만 있는지 두 저장소에서 검사합니다 |
| `npm test` | 단위 테스트 — 수식·엔진·참조·시트·병합·서식·정렬/필터/차트/댓글·붙여넣기·시트 확장·저장소·저널·읽기 실패 격리·아웃박스·`.env`·검사 도구 격리·회귀 |
| `npm run smoke` | 서버를 실제로 띄워 WebSocket 2명 접속 → 동시 편집 → 시트 조작 → 예전 형식 문서 변환 → CSV → 행 삽입 → 악의적 입력 → 재접속 → 저장 → 라우팅 |
| `npm run crash` | 저장 보장 — 서버를 강제 종료(SIGKILL)했다 다시 띄우기를 반복하며 기록이 살아남는지. 파일 저장소와 Supabase 저장소 **양쪽 모두**에서 |
| `npm run auth` | 비밀번호 잠금 — 페이지·API·WebSocket 차단, 세션 쿠키, 무차별 대입 차단, 잠금 꺼짐 상태 |
| `npm run browser` | 헤드리스 크롬 탭 2개로 실제 UI 조작 → 타이핑·수식·실시간 반영·시트 전환·시트간 실행취소·문서 목록·구링크 호환 |

`npm run check:writes` 는 빼놓아도 되는 검사가 아닙니다. "기록이 날아가지 않게" 지키는
마지막 관문이 그대로 있는지 확인하는 유일한 검사라서, 이것만 빼고 돌린 `verify` 는
**읽지도 못한 문서를 덮어쓸 수 있는 상태에 대고 "통과" 라고 말합니다.**

각 명령은 **마지막 줄에 그 실행의 숫자를 스스로 출력합니다.** 여덟 중 일곱은 통과한 검사
개수입니다:

- `npm run check:spec` · `npm run check:writes` · `npm run smoke` · `npm run crash` ·
  `npm run auth` · `npm run browser` → `smoke: OK — N checks passed.` 형태
- `npm test` → `N passed, 0 failed, N total`

**`npm run check:imports` 하나만 다릅니다.** 이건 `check-imports: OK — N files, …` 로
끝나는데, 여기서 N 은 통과한 검사 개수가 아니라 **훑어본 파일 수**입니다. 검사 개수로 읽으면
안 됩니다.

이 표에는 그 숫자를 적지 않습니다. 코드가 조금만 바뀌어도 숫자가 달라지는데 문서 쪽 숫자를
확인해 주는 장치가 없어서, 한 번 적어두면 조용히 거짓말이 되기 때문입니다 — 실제로 여기 적혀
있던 숫자들이 그렇게 틀려 있었습니다. 몇 개인지 궁금하면 명령을 돌려서 마지막 줄을 보세요.
위의 구분(일곱은 검사 개수, `check:imports` 는 파일 수)만 지키면 그게 언제나 맞는 답입니다.

`npm run crash` 의 Supabase 쪽은 `tools/fakesupabase.mjs`(메모리 안에서 도는 가짜
Supabase)를 상대로 돌기 때문에, 실제 계정이 없어도 두 저장소가 모두 검증됩니다.

`npm run browser -- --headed` 로 실제 창을 띄워 볼 수 있고, `-- --debug` 로 주고받은
WebSocket 프레임을 볼 수 있습니다. 스크린샷은 `docs/shots/` 에 저장됩니다 (`home.png` 문서
목록, `app.png` 편집 화면, `docs.png` 헤더 문서 패널, `new-doc.png` 갓 만든 문서).

### 검증은 `.env` 를 건드리지 않습니다

**`.env` 를 그대로 둔 채 `npm run verify` 를 돌리세요.** 이름을 바꿀 필요도, 옮길 필요도,
지울 필요도 없습니다.

이 검사들은 문서를 지우고 서버를 강제 종료하는 **파괴적인** 도구입니다. 그래서 `.env` 에
`SUPABASE_URL` 을 채워 둔 사람이 무심코 `npm run verify` 를 돌렸다가 **자기 실제 데이터베이스를
자기 테스트가 지워버리는** 일이 절대 없도록, 검사 도구는 `.env` 와 완전히 차단되어 있습니다.

차단하는 방식은 이렇습니다 (`tools/harness-env.mjs`).

- 검사 도구들은 `env.js` 를 부르지 않습니다. 그래서 도구 자신의 프로세스에는 `.env` 값이
  애초에 들어오지 않습니다.
- 도구가 서버를 띄울 때는 `SUPABASE_URL`·`SUPABASE_SERVICE_KEY`·`SUPABASE_SCHEMA`·
  `SZ_PASSWORD`·`SZ_PASSWORD_HASH`·`SZ_SESSION_SECRET`·`SZ_SESSION_DAYS` 를 **전부 빈 값의
  진짜 환경변수로 넣어서** 띄웁니다. 그 검사가 일부러 쓰겠다고 지정한 값만 예외입니다.
  위 [설정은 `.env` 파일에](#설정은-env-파일에-읽습니다-진짜로) 의 규칙 그대로, 환경변수는
  `.env` 를 이깁니다. 그러니 운영자의 `.env` 는 **파일을 건드리지 않은 채로** 무력화됩니다.
- 서버를 처음 띄우기 전에 **탐침 프로세스**가 진짜 `env.js` 를 불러 "서버가 실제로 보게 될
  값"을 되읽어옵니다. 혹시라도 `.env` 가 이겨버렸다면 서버가 하나도 뜨기 전에 중단합니다.
- 그래도 로컬이 아닌 Supabase 주소가 잡히면, 서버가 부팅 로그에 그 주소를 말하는 순간
  강제 종료시키고 멈춥니다.

`npm run auth` 는 잠금이 켜진 상태와 꺼진 상태를 **둘 다** 검사하는데, 꺼진 상태 검사도
이 방식으로 통과합니다. 서버는 `.env` 를 정말로 읽지만, 그 검사가 띄운 서버에는 빈
`SZ_PASSWORD` 가 먼저 도착해 있기 때문입니다.

(확인해 봤습니다. `.env` 에 `SZ_PASSWORD` 와 실제처럼 생긴 `SUPABASE_URL` 을 채워 둔 채로
`auth`·`smoke`·`crash`·`browser` 를 전부 돌렸고, 네 개 모두 평소와 똑같은 개수로 통과했으며
`crash` 는 `.env` 의 주소가 아니라 메모리 안의 가짜 Supabase 를 상대로 돌았습니다.)

## 외부에서 가져오기

엑셀이나 구글 시트에서 복사한 걸 붙여넣으면 **값뿐 아니라 서식과 병합까지** 따라옵니다.

| 가져오는 것 | 구글 시트 | 엑셀 | 시트지(다른 탭) |
|---|---|---|---|
| 값 | ✅ | ✅ | ✅ |
| 굵게·기울임·색·정렬·테두리·글꼴·크기 | ✅ | ✅ | ✅ |
| 병합된 셀 | ✅ | ✅ | ❌ ([아래](#시트지끼리-복사할-때-병합은-왜-안-오나요)) |
| 숫자 서식(통화·소수 자릿수·날짜 표시) | ❌ | ❌ | ❌ |
| 칸에 걸어 둔 링크 | ❌ | ❌ | ❌ |
| **수식** | ✅ | ❌ | ✅ |
| 수식의 상대 참조 자동 조정 | ❌ | — | ✅ |

숫자 서식은 어느 쪽에서도 오지 않습니다. 클립보드에 실려 오는 건 글자 모양(굵게·색·
테두리 같은 것)뿐이고, "이 칸을 통화로 보여라" 같은 표시 규칙은 실리지 않기 때문입니다.
값 자체는 그대로 오니, 표시 형식만 붙여넣은 뒤에 다시 골라 주시면 됩니다.

**링크도 어느 쪽에서도 오지 않습니다.** 링크가 걸린 칸을 붙여넣으면 글자는 그대로
들어오지만 링크는 빠집니다. 붙여넣은 뒤 `(서식 포함)` 이라는 안내가 떠도 마찬가지입니다 —
그 "서식" 에 링크는 들어 있지 않습니다. 필요하면 **링크 삽입** 으로 다시 걸어 주세요.

### 시트지끼리 복사할 때 병합은 왜 안 오나요

시트지가 복사할 때 만드는 표에는 병합 정보(`colspan`/`rowspan`)를 넣지 않습니다.
그래서 **시트지 → 시트지** 로 붙여넣으면 값·서식·수식은 오지만 병합은 오지 않고,
**붙여넣는 쪽에 원래 있던 병합이 그대로 유지됩니다.** 일부러 그렇게 했습니다 — 붙여넣기
한 번이 받는 쪽의 표 모양을 통째로 바꿔 버리지 않게 하려는 것입니다.

엑셀·구글 시트는 자기들 표에 `colspan`/`rowspan` 을 넣어 보내므로 그쪽에서 올 때는
병합도 같이 옵니다. 위 표의 차이는 그래서 생깁니다.

시트지끼리 옮길 때 병합이 필요하면, 붙여넣은 다음 받는 쪽에서 직접 병합해 주세요.

### 엑셀 수식이 안 오는 이유

**엑셀은 복사할 때 클립보드에 계산된 값만 담고 수식은 담지 않습니다.** 이건 시트지의 한계가
아니라 엑셀이 보내주지 않는 것이라, 어떻게 해도 가져올 수 없습니다. 그래서 엑셀에서 붙여넣으면
"값만 가져왔다"는 안내가 한 번 뜹니다 — 모르고 계시다가 나중에 수식이 사라졌다고 오해하시면
안 되니까요.

엑셀 수식까지 옮기려면 `.xlsx` 파일을 직접 여는 기능이 필요하고, 그건 별도 작업입니다.

### 상대 참조가 조정되지 않는 경우

구글 시트에서 `=A1+B1` 을 복사해 다른 위치에 붙여넣으면 **`=A1+B1` 그대로** 들어옵니다.
구글 시트의 클립보드에는 그 수식이 원래 어느 칸에 있었는지가 없어서, 조정하려면 추측해야
합니다. 추측이 틀리면 **틀린 숫자가 조용히 들어가므로**, 복사한 그대로 넣는 쪽을 택했습니다.

시트지끼리는(다른 탭·다른 창 포함) 출처를 함께 보내므로 정상적으로 조정됩니다.

### 안전

붙여넣는 HTML은 출처를 알 수 없는 남의 코드이고, 그 결과가 여러 사람이 함께 보는 문서에
들어갑니다. 그래서 스크립트가 실행되지 않는 별도 해석기로 열어 **필요한 값만** 꺼내고
나머지는 전부 버립니다. 색은 시트지가 아는 표기(`#rgb`, `#rrggbb`, `#rrggbbaa`,
`rgb()`/`rgba()`, 정해 둔 색 이름 목록)만 받아 전부 `#rrggbb` 로 바꿔 넣고, `transparent`·
`inherit`·`var()`·그라데이션처럼 모르는 값은 버립니다. 글꼴은 시트지가 가진 목록에 이름이
있을 때만 남깁니다. 마크업의 값을 그대로 갖다 쓰는 경로는 없습니다.

같은 이유로 **`<style>` 블록의 CSS 클래스는 읽지 않습니다.** 남의 스타일시트를 해석하려면
그 안의 규칙을 그대로 실행해 주는 셈이 되기 때문입니다. 그래서 서식을 칸에 직접 적어 보내지
않고 클래스로만 보낸 칸은 **서식 없이 들어옵니다.** 엑셀은 보통 두 가지를 같이 보내서 위 표대로
따라오지만, 어쩌다 클래스에만 들어 있던 서식은 빠질 수 있습니다.

## 접속 비밀번호

사이트 전체에 **비밀번호 하나**를 겁니다. 사람별 계정은 없습니다 — 비밀번호를 아는 사람은
모든 문서를 읽고 쓸 수 있습니다.

### 켜는 법

**내 컴퓨터에서 켤 때**가 가장 간단합니다. `.env` 파일에 두 줄을 채웁니다
(`.env.example`을 복사해서 만드세요):

```
SZ_PASSWORD=원하는_비밀번호
SZ_SESSION_SECRET=<아래 명령으로 만든 긴 문자열>
```

**인터넷에 공개하는 서버라면 `SZ_PASSWORD` 대신 아래의 `SZ_PASSWORD_HASH` 를 쓰세요.**
비밀번호 원문을 호스팅 대시보드에 남기지 않기 위해서입니다.

이 파일은 서버가 **시작할 때 읽습니다.** 대시보드가 있는 호스팅(Render 등)에서는 파일
대신 대시보드의 환경변수에 같은 이름으로 넣으면 되고, 같은 이름이 양쪽에 다 있으면
환경변수가 이깁니다. 자세한 규칙은 위 [설정은 `.env` 파일에](#설정은-env-파일에-읽습니다-진짜로) 참고.

세션 서명용 문자열은 이렇게 만듭니다:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

서버를 다시 켜면 잠깁니다. 부팅 로그에 잠금 여부가 **항상** 표시됩니다. 켜졌다면 이렇게
나옵니다:

```
[시트지] 접근 제한이 켜져 있습니다 — 공유 비밀번호 하나로 사이트 전체를 보호합니다 (세션 14일).
```

`접근 제한이 꺼져 있습니다` 가 보이면 비밀번호가 서버에 전달되지 않은 것입니다. 그 상태로
인터넷에 올라가 있으면 주소를 아는 누구나 다 읽고 쓸 수 있으니, 로그를 꼭 확인하세요.

**인터넷에 공개할 서버라면 원문 대신 해시를 넣으세요.** 이때 `SZ_PASSWORD` 는 비우고
`SZ_PASSWORD_HASH` 만 채웁니다 (둘 다 있으면 해시가 이깁니다):

```bash
npm run hash-password     # 물어봅니다. 입력한 글자는 화면에 안 보입니다
```

`scrypt$...` 로 시작하는 한 줄이 나옵니다. 그 줄을 `SZ_PASSWORD_HASH=` 에 넣고
`SZ_PASSWORD` 는 비웁니다. 그러면 비밀번호 원문은 `.env` 에도, 서버 로그에도 남지 않습니다.

비밀번호를 **명령에 직접 적는 방법**(`npm run hash-password -- 원하는_비밀번호`)도 되지만,
물어보는 입력이 안 되는 터미널일 때만 쓰세요. 그렇게 하면 비밀번호가 프로세스 목록에 잠깐
보이고, 무엇보다 **PowerShell 의 명령 기록 파일에 글자 그대로 남습니다.** 그 파일은
`%APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt` 이고,
**창을 닫아도 컴퓨터를 껐다 켜도 지워지지 않습니다.** 지우려면 그 창을 닫고 PowerShell 을
새로 연 다음 이 한 줄을 실행하세요 (기록 파일을 통째로 지웁니다):

```powershell
Remove-Item (Get-PSReadLineOption).HistorySavePath
```

단계별 절차는 [`docs/DEPLOY.md`](docs/DEPLOY.md) 1단계에 있습니다.

### 무엇이 잠기나

- 모든 페이지와 API
- **실시간 편집 통로(`/ws`)** — 이게 핵심입니다. 이 통로 하나로 모든 문서를 읽고 쓸 수
  있어서, 화면만 막고 여기를 열어두면 자물쇠가 없는 것과 같습니다
- 열려 있던 연결도 세션이 만료되면 끊기고 다시 로그인해야 합니다

`/healthz`(서버 상태 확인)와 로그인 화면 자체는 열려 있습니다.

### 알아두실 것

| 항목 | 내용 |
|---|---|
| 로그인 유지 | 기본 14일. `SZ_SESSION_DAYS` 로 조정 |
| 무차별 대입 방어 | 15분에 10번 틀리면 차단. 그동안은 맞는 비번도 막힙니다 |
| 전원 로그아웃 | `SZ_SESSION_SECRET` 이나 비밀번호를 바꾸면 모두 로그아웃됩니다 |
| **HTTPS 필수** | 아래 참고 |

**HTTPS 없이 인터넷에 공개하면 비밀번호가 평문으로 오갑니다.** 같은 와이파이에 있는 사람이
그대로 읽습니다. Render·Railway·Fly.io 같은 곳은 HTTPS를 자동으로 붙여주고, 앱은 그 뒤에서
동작하도록 만들어져 있습니다(`trust proxy`, `Secure` 쿠키).

`.env` 는 `.gitignore` 에 들어 있어 깃허브에 올라가지 않습니다. **지우지 마세요.**

## 저장소 — 파일 또는 Supabase

문서를 어디에 저장할지는 설정 하나로 정해집니다.

| 설정 | 저장되는 곳 |
|---|---|
| `SUPABASE_URL` 비었음(기본) | 이 서버의 `data/` 폴더. JSON 스냅숏 + 기록 로그 + 백업 5벌 |
| `SUPABASE_URL` 채움 | Supabase(Postgres) 데이터베이스 |

**저장소를 고르는 건 `SUPABASE_URL` 하나입니다.** 값이 있으면 Supabase 를 쓰고, 비어 있으면
파일을 씁니다. `SUPABASE_URL` 만 넣고 `SUPABASE_SERVICE_KEY` 를 빠뜨리면 파일 저장소로
돌아가는 게 아니라 **서버가 그 자리에서 멈추고 무엇이 비었는지 말합니다.** 일부러 그렇게
만들었습니다 — 운영자가 데이터베이스에 저장되고 있다고 믿는 동안 조용히 로컬 디스크에 쌓이는
쪽이 훨씬 위험하기 때문입니다.

**파일 저장**은 설치가 필요 없지만 그 디스크가 유일한 사본입니다. 디스크가 날아가거나
컨테이너가 재배포되면서 폴더가 초기화되면 문서도 같이 사라집니다.

**Supabase 저장**을 쓰려면 순서대로 하면 됩니다.

1. supabase.com 에서 프로젝트를 하나 만듭니다(무료 등급으로 충분합니다).
2. `docs/supabase.sql` 파일 내용을 전부 복사해 Supabase 의 **SQL Editor** 에 붙여넣고
   실행합니다. 표 3개(`sz_documents`, `sz_journal`, `sz_backups`)가 만들어집니다.
   그 파일 맨 위에 클릭 순서까지 적어 두었습니다.
3. `SUPABASE_URL` 과 `SUPABASE_SERVICE_KEY` 를 `.env`(또는 호스팅 대시보드 환경변수)에
   넣습니다. 두 값 다 **Project Settings** 에 있습니다.

   | 넣을 값 | 대시보드에서 어디 |
   |---|---|
   | `SUPABASE_URL` | **Data API** 화면 맨 위 `Project URL` (`https://<프로젝트>.supabase.co`) |
   | `SUPABASE_SERVICE_KEY` | **API Keys** 화면의 **`Secret keys`** — `sb_secret_...` 값. 가려져 있으니 눈 모양 아이콘으로 펼친 뒤 복사 버튼으로 복사하세요 |

   같은 **API Keys** 화면의 **`Publishable key`**(`sb_publishable_...`)는 여기에 넣는
   값이 **아닙니다.** 브라우저에 노출돼도 되는 공개용이라 2번에서 만든 표 3개에는 권한이
   하나도 없습니다. 잘못 넣으면 서버는 켜지기 전에 그걸 알아보고
   `SUPABASE_SERVICE_KEY 에 공개용(publishable) 키가 들어 있습니다` 를 남기고 멈춥니다 —
   사이트가 멀쩡히 뜬 채로 저장만 조용히 실패하는 일은 없습니다.

   예전에 만든 프로젝트라면 같은 화면의 **`Legacy anon, service_role API keys`** 탭에
   있는 `service_role` 값(`eyJ...`)도 그대로 씁니다. 두 형식 중 아무 쪽이든 하나면
   되고, 어느 쪽인지 알려 주는 설정은 없습니다 — 서버가 값의 생김새를 보고 맞춥니다.
   다만 Supabase 가 옛 키들을 **2026년 말에 없앨 예정**이라, 새로 넣는다면
   `sb_secret_` 쪽이 낫습니다. (옛 `anon` 키는 `Publishable key` 와 마찬가지로
   여기에 넣는 값이 아닙니다.)
4. 서버를 켜고 로그에 `문서 저장소: Supabase (...)` 가 뜨는지 확인합니다.
   `문서 저장소: 파일` 이 뜨면 설정이 전달되지 않은 것입니다.
   바로 다음 줄 `Supabase 키 형식: ...` 은 넣은 키의 **형식만** 알려 줍니다(값은 로그에
   찍히지 않습니다). `새 형식 비밀 키 (sb_secret_)` 또는 `레거시 JWT 키 (service_role)`
   이면 제대로 넣은 것입니다.
5. **문서 목록에 `시작 시트` 라는 문서가 하나 보입니다. 이게 정상입니다.** 저장소가 텅
   비어 있으면 서버가 견본 문서를 하나 만들어 넣기 때문입니다. 켤 때 로그에도 이렇게
   찍힙니다:

   ```
   [시트지] 시작 문서를 만들었습니다: 시작 시트 (start1)
   [시트지] 문서 1개를 불러왔습니다.
   ```

   **이 문서는 `data/` 에서 넘어온 게 아닙니다.** 방금 만들어진 예시(월별 매출 숫자가
   들어 있는 견본)입니다. 하필 문서 번호가 `data/start1.json` 과 똑같은 `start1` 이라
   헷갈리기 쉬운데, 서로 아무 관계도 없습니다.

   - **이 시점에 예전 문서는 하나도 넘어와 있지 않습니다.** 옮기려면 아래 절차를 직접
     밟아야 합니다.
   - 견본이 거슬리면 지워도 됩니다. 지워도 `data/` 폴더의 파일에는 아무 일도 안 일어납니다.
   - `data/` 폴더의 예전 문서는 그대로 남아 있습니다 — 바로 아래를 읽어 주세요.

> 이미 `data/` 에 옮기고 싶은 문서가 있다면 **아래 "기존 문서는 어떻게 되나요" 를 먼저
> 읽고 시작하세요.** 서버를 켜는 순서가 위 3~4번과 다릅니다.

`SUPABASE_SERVICE_KEY` 는 데이터베이스 전체를 여는 열쇠입니다. 서버 쪽에만 두세요.
브라우저로 내려가지 않고, 로그·오류 메시지에도 절대 찍히지 않습니다. (이름은 예전 키
이름인 `service_role` 에서 왔지만 뜻은 그냥 "비밀 키" 입니다. 지금 대시보드가 주는
`sb_secret_...` 과 옛 `service_role`(`eyJ...`) 을 둘 다 받습니다.)

### Supabase 로 바꾸면 기존 문서는 어떻게 되나요

**`data/` 폴더는 그대로 있습니다.** 이것부터 말씀드립니다.

- Supabase 로 바꿔도 서버는 `data/` 폴더를 **읽지도, 고치지도, 지우지도 않습니다.**
  파일 하나 건드리지 않습니다. 폴더를 새로 만들지도 않습니다.
- 그래서 화면에서 예전 문서가 안 보이는 건 **사라져서가 아니라, 서버가 이제 다른 곳을
  보고 있어서**입니다.
- `.env` 의 `SUPABASE_URL` 을 도로 비우고 서버를 껐다 켜면 예전 문서가 그대로 다시
  나타납니다. 언제든 되돌아올 수 있습니다.

**옮겨 주는 도구는 없습니다.** 예전에 `npm run migrate-to-supabase` 라는 도구가 있었지만
지웠습니다. 실제 자료를 상대로 한 번에, 되돌릴 수 없게 쓰는 도구인데, 점검에서 이런 것들이
나왔기 때문입니다 — 자기가 손대서 열 수 없게 만들어 놓은 문서를 "복사됨" 이라고 보고하고,
이미 덮어쓴 뒤에 "아무것도 쓰지 않았습니다" 라고 찍고, 데이터베이스에 있던 더 새 문서를
디스크의 더 오래된 파일로 되돌려 놓았습니다. 옮길 문서가 몇 개 안 되는데 이런 도구를
두는 건 남는 장사가 아니라서 없앴습니다. 대신 아래 방법을 쓰시면 됩니다.

#### 내용을 옮기는 방법 — 탭 두 개에서 복사·붙여넣기

시트 한 장씩, 손으로 옮깁니다. 몇 장 안 되면 몇 분이면 끝납니다.

먼저 **서버를 두 개 켭니다.** 하나는 예전 방식(파일), 하나는 새 방식(Supabase)입니다.
서버는 켜질 때 `.env` 를 한 번 읽고 마니까, **순서가 중요합니다.**

1. `.env` 의 `SUPABASE_URL` 이 **아직 비어 있는 상태에서** 서버를 켭니다.

   ```bash
   npm start
   ```

   로그에 `문서 저장소: 파일 (data/ 디렉터리)` 가 보여야 합니다. 이 창은 **끄지 말고
   그대로 두세요.** 여기가 예전 문서입니다 → http://localhost:3000

2. 이제 `.env` 를 열어 `SUPABASE_URL` 과 `SUPABASE_SERVICE_KEY` 를 채우고 저장합니다.
   1번에서 켜 둔 서버는 아무 영향도 받지 않습니다. 켤 때 이미 다 읽었기 때문입니다.

3. **새 터미널 창**을 하나 더 열고, 다른 포트로 서버를 하나 더 켭니다.

   ```bash
   PORT=3001 npm start          # macOS / Linux / Git Bash
   $env:PORT=3001; npm start    # PowerShell
   ```

   로그에 `문서 저장소: Supabase (...)` 가 보여야 합니다. 여기가 새 문서입니다 →
   http://localhost:3001

   > 비밀번호(`SZ_PASSWORD`)를 걸어 두셨다면 `.env` 에 `SZ_SESSION_SECRET` 도 반드시
   > 채워져 있어야 합니다. 로그인 쿠키는 포트를 구분하지 않아서, 이 값이 비어 있으면
   > 서버 두 개가 서로 다른 임시 키를 만들고 한쪽에 로그인할 때마다 다른 쪽이 로그아웃
   > 됩니다. 만드는 법은 [켜는 법](#켜는-법) 에 있습니다.

4. 브라우저 탭 두 개를 나란히 엽니다. **3000 = 예전 문서**, **3001 = 새 저장소**.
   3001 쪽 목록에는 `시작 시트`(견본) 하나만 보입니다. 견본이지 옮겨온 문서가 아닙니다.

5. 3001 쪽에서 문서를 새로 만듭니다. 견본에 덧쓰지 말고 새로 만드세요 — 나중에 어느 게
   옮긴 것이고 어느 게 견본이었는지 헷갈리지 않습니다. 옮길 문서에 시트 탭이 여러 장이면,
   왼쪽 아래 `+` 로 같은 수만큼 시트 탭을 먼저 만들어 둡니다.

6. **시트 크기를 먼저 맞춥니다. 이 단계가 제일 중요합니다.** 예전 시트가 새 시트보다
   넓거나 길면, 넘치는 부분은 **아무 말 없이 버려집니다.**

   - 화면 아래 상태줄에 `200행 x 52열` 처럼 시트 크기가 적혀 있습니다. 양쪽을 비교하세요.
   - 새로 만든 시트는 `200행 x 26열` 입니다.
   - 그리드 아래의 `오른쪽에 열 [26] 개 추가` 로 열을, 모자라면
     `맨 아래에 행 [1000] 개 추가` 로 행을 늘려 예전 시트 이상으로 맞춥니다.

7. 3000 탭에서 옮길 시트 탭을 고르고 → 아무 칸이나 클릭 → `Ctrl+A` → `Ctrl+C`.

8. 3001 탭의 같은 자리 시트 탭으로 가서 → `A1` 칸을 클릭 → `Ctrl+V`.

9. 시트 탭마다 7~8 을 반복합니다. 문서가 여러 개면 문서마다 반복합니다.

10. 다 옮겼으면 1번 창(3000)을 `Ctrl+C` 로 끕니다. 이제부터는 `.env` 그대로 `npm start`
    하나만 켜면 Supabase 쪽으로 붙습니다.

**다 옮긴 뒤에도 `data/` 폴더는 지우지 마세요.** 며칠 써 보고 데이터베이스에 제대로
들어갔다는 확신이 선 다음에 직접 지우셔도 늦지 않습니다. 지우는 건 언제든 할 수 있지만
되돌리는 건 못 합니다.

##### 이 방법으로 따라오는 것 / 안 따라오는 것

| 따라옵니다 | 따라오지 않습니다 |
|---|---|
| 칸에 적힌 값 | 병합된 칸 — 붙여넣는 쪽의 병합은 그대로 남습니다 |
| 수식 (상대 참조는 붙여넣는 위치에 맞게 조정됩니다) | 숫자 서식(통화·소수 자릿수·날짜 표시). 값 자체는 그대로 옵니다 |
| 굵게·기울임·밑줄·취소선 | 줄바꿈·글자 회전 설정 |
| 글자색·배경색·가로 정렬·세로 정렬 | **칸에 걸어 둔 링크** — 아래를 꼭 읽어 주세요 |
| 글꼴·글자 크기·테두리 | 열 너비·행 높이·틀 고정 |
|  | 필터·차트·댓글, 시트 탭의 이름과 색 |

오른쪽 칸에 있는 것들은 새 문서에서 다시 지정해 주시면 됩니다. **값과 수식이 온다**는
게 핵심입니다. 병합은 붙여넣기 전에 새 문서 쪽에서 직접 해 두셔도 되고, 붙여넣은 다음에
하셔도 됩니다.

**링크는 특히 조심하셔야 합니다.** 다른 것들은 안 따라온 게 눈에 보이는데, 링크는
**보이지 않게** 빠집니다 — 글자는 그대로 오고, 붙여넣은 뒤 `…칸을 붙여넣었습니다
(서식 포함)` 이라는 안내까지 뜨는데, 그 "서식" 에 링크는 들어 있지 않습니다. 클릭해 보기
전까지는 알 수 없습니다. 링크를 걸어 둔 칸이 있는 시트를 옮겼다면, 옮긴 뒤에 그 칸들을
찾아 **링크 삽입** 으로 다시 걸어 주세요.
(붙여넣는 쪽 칸에 원래 링크가 걸려 있었다면 그건 지워지지 않고 그대로 남습니다. 글자만
새것으로 바뀌고 링크는 옛날 주소를 가리키게 되니, 그 경우엔 **제거** 를 눌러 주세요.)

**한 번에 붙여넣을 수 있는 칸은 20000칸까지입니다.** `Ctrl+A` 는 값이 있는 부분만이
아니라 **시트 전체**를 고릅니다. 그래서 시트가 그보다 크면
`한 번에 편집할 수 있는 칸은 20000개까지입니다` 라고 뜨면서 아무것도 붙지 않습니다.
그럴 때는 `Ctrl+A` 대신 마우스로 위쪽 절반, 아래쪽 절반을 나눠 끌어서 두 번에 옮기세요.
(기본 크기 200행 x 26열은 5200칸이라 한 번에 됩니다.)

> 도메인·Cloudflare·Supabase 까지 한 단계씩 적어 둔 문서이고, **환경 변수에 무엇을 넣고
> 무엇을 넣지 말아야 하는지는 그 문서가 기준입니다.** 아래는 개요일 뿐이니, 두 문서가
> 달라 보이면 `docs/DEPLOY.md` 를 따르세요.

**배포 = 남의 컴퓨터에서 24시간 켜 두기.** 처음이라면 Render 같은 곳이 제일 쉽습니다.

1. 코드를 깃허브 저장소에 올립니다. `.env` 는 `.gitignore` 에 있어서 **올라가지 않습니다**
   (그게 맞습니다. 비밀번호를 깃허브에 올리면 안 됩니다).
2. Render 에서 `New` → `Web Service` → 그 저장소를 고릅니다.
3. 빌드 명령은 `npm install`, 시작 명령은 `npm start` 입니다.
4. **환경변수(Environment / Environment Variables) 화면에서 값을 넣습니다.** 배포된
   서버에는 `.env` 파일이 없습니다 — 대신 이 화면이 `.env` 역할을 합니다. 이름은 똑같이
   씁니다.

   | 이름 | 값 |
   |---|---|
   | `SZ_PASSWORD_HASH` | `npm run hash-password` 가 출력한 `scrypt$...` 한 줄 (**반드시 채우세요**) |
   | `SZ_SESSION_SECRET` | 길고 임의한 문자열 ([만드는 법](#켜는-법)) |
   | `SUPABASE_URL` | Supabase 를 쓸 때만 |
   | `SUPABASE_SERVICE_KEY` | Supabase 를 쓸 때만 — `Secret keys` 의 `sb_secret_...` (또는 옛 `service_role`) |

   **`SZ_PASSWORD`(비밀번호 원문)는 대시보드에 넣지 마세요.** 그 화면을 볼 수 있는 사람에게
   비밀번호가 그대로 보이고, `SZ_PASSWORD_HASH` 가 있으면 어차피 무시됩니다. 게다가
   **무시됐다는 사실이 로그에 찍히지 않아서** 넣은 사람은 그걸 알 방법이 없습니다.
   공개 서버에는 해시만 넣으세요.

   `PORT` 는 대부분의 호스팅이 알아서 넣어 줍니다. 직접 넣지 않아도 됩니다.
5. 배포 후 **로그를 한 번 읽어보세요.** `접근 제한이 켜져 있습니다` 와 원하는
   `문서 저장소:` 줄이 보여야 합니다.

**주의할 점:**

- **비밀번호를 반드시 켜세요.** [접속 비밀번호](#접속-비밀번호) 참고. 켜지 않으면
  URL을 아는 사람은 누구나 읽고 쓸 수 있습니다.
- `data/` 는 로컬 파일이므로, 컨테이너를 재배포하면 사라지는 환경에서는 영구 볼륨을 붙이거나
  위의 Supabase 저장소를 쓰세요.
- 여러 서버 인스턴스로 늘리면 파일 저장소에서는 문서가 인스턴스별로 갈라집니다. 한 대로
  운영하거나 Supabase 저장소를 쓰세요.
- 백업: 파일 저장소는 `data/` 폴더만 복사하면 되고, Supabase 는 대시보드의 백업 기능을
  씁니다.

## 한계

정직하게 적어둡니다.

- **비밀번호는 하나뿐, 사람별 구분이 없습니다** — 비밀번호를 아는 사람은 **모든 문서를
  읽고 쓸 수 있습니다.** 누가 무엇을 고쳤는지 권한으로 나누는 기능은 없습니다.
  사람별 계정이 필요하면 별도 작업입니다
- **동시 편집 충돌 해결은 셀 단위 최종 쓰기 우선** — 두 사람이 같은 셀을 동시에 고치면
  나중 것이 이깁니다. 같은 셀 안의 글자를 문자 단위로 병합하지는 않습니다
- **시트간 수식 참조는 아직 안 됩니다** — `=시트2!A1`을 쓰면 `#REF!`와 함께
  "다른 시트 참조는 아직 지원하지 않습니다"라고 알려줍니다. 문법 해석·저장·복원은 이미
  되어 있고 계산만 빠져 있어서, 나중에 붙일 때 파서를 건드릴 필요가 없습니다
  (자세한 내용은 `docs/SPEC.md` 16장)
- **조건부 서식·피벗 테이블 없음** — 차트와 정렬·필터는 있습니다
- **최대 크기** 시트당 5,000행 × 702열(ZZ), 문서당 시트 50장
- **모바일 최적화 안 됨** — 데스크톱 브라우저 기준
- **저장 보장에도 구멍은 있습니다** — 프로그램이 죽는 것(강제 종료, 재시작)은 견디지만,
  기록을 디스크에 확실히 눌러 담는 건 0.2초에 한 번입니다. 그래서 **컴퓨터 자체의 전원이
  갑자기 나가면** 마지막 0.2초 안에 친 글자는 잃을 수 있습니다. 그리고 파일 저장소는
  그 디스크 하나가 전부라, 디스크가 죽으면 같이 죽습니다 — 그게 위의
  [Supabase 저장소](#저장소--파일-또는-supabase)가 있는 이유입니다. 브라우저 쪽 임시 보관은
  탭이 닫히는 건 견디지만 브라우저 데이터를 통째로 지우면 같이 지워집니다

## 코드를 고칠 때

`docs/SPEC.md` 가 모듈 간 계약서입니다. 함수 시그니처·AST 형태·통신 프로토콜이 모두 여기 적혀
있고, `npm run check:spec` 이 코드와 문서가 어긋났는지 검사합니다.
**동작을 바꿀 때는 스펙을 먼저 고치고 코드를 맞추세요.** 순서가 뒤집히면 검사가 무의미해집니다.

`shared/` 아래 코드는 Node와 브라우저 양쪽에서 돌아갑니다. `node:` 모듈이나 `window`,
`document` 를 쓰면 `check:imports` 가 잡아냅니다.

**`storage/` 를 고칠 때는 `npm run check:writes` 를 꼭 돌리세요.** 두 저장소에는 "읽어보지
못한 문서에는 손대지 않는다" 는 관문이 하나씩 있고, 파일을 쓰거나 데이터베이스에 쓰는 호출은
**전부** 그 관문 안에만 있어야 합니다. 같은 실수가 세 번 연속으로 다른 자리에서 나왔기
때문에 사람이 기억하는 대신 이 검사가 지킵니다. 새 호출을 관문 밖에 두면 여기서 멈춥니다.

**이 README 는 거의 전부 자동으로 검사되지 않습니다.** `check:spec` 이 잡아주는 것은 딱
세 가지뿐입니다 — "이미 있는 기능을 없다고 우기는 문장", 위의 **함수 개수**(`함수 N개` 라고
적힌 곳 전부), 그리고 위의 **함수 목록 표**. 이 셋은 틀리면 `npm run verify` 가 멈춥니다.

나머지 — 설명·절차·다른 숫자·로그 예시·`.env` 사용법 — 는 아무도 대신 확인해 주지 않습니다.
그래서 여기에는 **직접 돌려보고 확인한 것만** 적습니다. 확인할 방법이 없는 문장은 적지 말고
지우는 편이 낫습니다 — 틀린 설명서는 없는 설명서보다 나쁩니다. 사람이 그걸 믿고 배포 결정을
내리니까요.

숫자를 새로 적으려거든 먼저 물어보세요: **이게 틀어졌을 때 누가 알려주나?** 알려줄 사람이
없으면 숫자 대신 "명령을 돌려서 마지막 줄을 보라"고 적으세요.
